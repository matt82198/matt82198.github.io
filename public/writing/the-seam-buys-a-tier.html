The Seam Buys a Tier

Give a small model the seat and it climbs about one tier on tractable work — and stops climbing exactly where the repair loop would have to begin.

Previously: seated context flipped a frontier model on one hard item. This note asks the harder question — does the seat lift a whole weak model on real, multi-file repair work?

The setup

Same twelve tasks, two seats

Twelve seeded-defect repositories, each graded by a hidden pytest oracle — short single-file bugs, medium cross-file bugs, and long multi-module bugs. Five model tiers repair each one three times, in two conditions:

Unseated (U) — the raw model, one shot: task statement plus the repo files, return a patch. No scaffold. Seated (S) — the same task through the aesop worker seam: scoped context, dispatch template, and a structured submission channel. The oracle is identical; the only variable is the seat.

The headline, in one line

haiku, seated (67%) ≈ fable, unseated (69%). On this task mix, the seam is worth about one full tier to a small model — the exact "Haiku is enough inside the seat" claim, quantified.

Where it stops — and why that matters most

The lift is real on short work and gone on long

Split the same runs by task horizon and the compression has a hard edge. Seating helps on short and medium bugs; on the long, multi-module ones — the band where the unseated gap was widest — it does nothing.

The honest reason the long band is flat

These tasks ship no visible tests — only the hidden grading oracle — so the seam's iterative repair loop had nothing to iterate against. The seated arm here is single-pass: scoped context and structure, but no feedback cycle. Short bugs a small model can one-shot with good context; long-horizon bugs are exactly where you'd need the loop that never fired. So this note measures the seam's context, not its loop.

Methodology · green is not correct

Every number here was defended, not trusted

The same discipline as the first note, and it earned its keep. Both harnesses looked green on mocked tests while failing on the real path; the true numbers only appeared after running the actual thing and refusing a suspiciously clean result. What got fixed on the way to this table:

  1. The oracle never ran. The sandbox copied code flat; pytest oracle found nothing and scored every run a fail — a uniform 0/all that looked like total model failure. It was the harness.
  2. Correct fixes were rejected for wrong line numbers. Frontier models emit diffs with slightly-off @@ headers; strict apply refused them while a weaker model's exact-line diff slipped through — inverting the ranking until a content-based applier fixed it.
  3. The seated arm called an empty API. Wrong auth header and env var, an argument the shell helper rejected, a result object unpacked as a tuple — three transport bugs, all masked by a fake backend that never made a call.
  4. "Refusal" wasn't refusal. With no visible test to pass, the seated loop mislabeled every correct submission as a refusal — until success was re-gated on the worker's own output and the hidden oracle.

Nine distinct harness defects between the question and this chart. None reached a published number, because a clean-looking result was treated as a claim to disprove, not a finding to ship.

Update · 2026-07-28 · the loop ran, and it disproved the tidy story

This note first predicted the seam's repair loop would close the long-horizon gap that context alone left flat. We gave each task a visible reproduction test so the loop could engage, and ran it. It did not. The loop helped short and medium work — and barely touched the long band. What moved the long band was something simpler.

What runs next → what actually happened

A failing test beats iteration

Two findings, both against the prediction:

The reproduction test — not the loop — is the long-horizon lever. Simply placing a concrete failing test in the one-shot, unseated context lifted the long band from 43% → 60% (+17pp). A clear specification of the broken behavior does more for hard multi-module work than any scaffolding — the model was rarely short on tries, it was short on knowing exactly what "correct" meant.

The loop, on top of that spec, added almost nothing on the long band (60% → 58%). And it barely fired: across 161 seated runs, only 16 used a single repair and just 2 used a second. With a good spec, models either land it first attempt or can't recover with feedback — iteration wasn't the binding constraint. On short and medium work the seat still helped (+12 / +8pp); on the long band, the frontier gap held. gpt-4o-mini scored 0/12 on long-horizon tasks in every single condition — unseated, seated, spec, loop. No configuration here closed it.

The honest reversal

Two field notes, one method: predict, run the real thing, and let it disprove you. The seat buys a tier on tractable work — that held. The loop closes the long-horizon gap — that didn't. What helped hard work most was the cheapest thing on the table: telling the model, concretely, what "fixed" looks like.

What this is not

A bounded result, stated as one. N is small — 12 tasks, 3 repeats, n=36 per tier per arm; these are directional, not confidence intervals. The seated arm is single-pass; the seam's repair loop is untested here. Nine seated "refusals" (fable 6, opus 2, haiku 1) count as fails and slightly understate those tiers. Both arms count a patch that doesn't apply or fix as a failure, consistently. This is a receipt about where context carries a small model, and an honest marker of where the loop still has to prove itself.
