Aesop · Release2026-07-25 · v0.4.0

Two swappable seats

Bring your own model to the seat that codes and the seat that judges — from one config block.

npmnpm i @matt82198/aesop@0.4.0·npx @matt82198/aesop init

What shipped

Aesop is a crash-only multi-agent orchestration harness: agent behavior lives in durable, human-diffable files, and recovery is re-reading from disk. 0.4.0 makes the model in each seat a replaceable part. There are two seats, and you now select the backend + model for each from a single seats block in aesop.config.json — no code changes.

Worker seatlive

The seat that executes — writes code, runs tests. Claude Code, Codex, or any OpenAI-compatible endpoint (OpenRouter, a local Ollama, your own gateway).

Orchestrator seatlive

The seat that judges — the final_catch ship/block decision now routes through the configured backend. Defaults to the in-session harness, so nothing changes until you opt in.

{
  "seats": {
    "worker":       { "backend": "openai-compatible", "model": "…",
                      "base_url": "http://localhost:11434/v1", "is_local": true },
    "orchestrator": { "backend": "openai-compatible", "model": "gpt-4o-mini",
                      "api_key_env": "OPENAI_API_KEY" }
  }
}
# no seats block? byte-identical to before: Claude worker + in-session orchestrator.

The human interface (the run Report) and the state layer (STATE, tracker, receipts, recovery journal) are invariant across a swap — verified end-to-end, offline and on a live run where worker and orchestrator both ran a non-Claude model and the output shape matched exactly.

Why a swappable judge matters

Context is what makes the seat decide

The companion field note (Context at the Seam) measured it: on the hardest, synthesis-heavy item, giving the judge seat real repository context flips it from abstention to a correct refutation — and that held on both a frontier model and a commodity one at ~1/7 the cost. A swappable, context-fed judgment seat is the point, not a curiosity.

Also in 0.4.0 — hardening

  • npx aesop init now scaffolds the full driver/ seam (it was silently omitted).
  • SSRF validation on backend URLs (IPv6 + DNS), is_local pinned to loopback, api_key_env restricted so a shared config can't exfiltrate an arbitrary secret.
  • Process-tree timeouts on verification commands (no more wedged waves), bounded response reads, fail-closed CI merge gating.

All of it earned its version number: two adversarial audit passes per feature, then a six-round self-audit loop that caught a flagship-config crash, a keyless-exfil bypass, and a coordination gate that had been dead code — each fixed and re-attacked before release.

Honest bounds

Single-instance is sound. The multi-instance claim/coordination lifecycle (lease renewal, crash-orphan recovery) is scoped to scheduled state-layer work — documented, not hidden. Seat decision quality is a separate, ongoing measurement (the bench line), distinct from the plumbing that this release proves.
